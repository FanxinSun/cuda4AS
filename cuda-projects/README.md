# cuda-projects — third-party CUDA, as input to the translator

Shallow clones (`--depth 1`, no submodules) of 28 public CUDA repositories.
The clones themselves are gitignored (`cuda-projects/*/`); what is tracked is
this file and `corpus.json`, which pins each repository to the commit that was
read. Regenerate with `python3 -I tools/cuda_projects.py manifest`.

Nothing in here is edited. Treat it like `lmz/` -- with one exception: after the baseline,
`python3 -I tools/cuda_projects.py ready --apply` **thinned the bench clones**. Programs that passed on a
real GPU moved to `ready/<dir>/` (see below), and unfinished teaching exercises were removed. What is left in
a bench clone is what has not passed yet. Any removed file comes back with `git -C cuda-projects/<dir> checkout -- <path>`.
`corpus.json` therefore stays frozen: `manifest` refuses to rerun on thinned clones (`--force` only on fresh ones).

## Verification done on the Mac

- all 28 clones: `git fsck` clean, working tree clean, commit pinned in `corpus.json`
- 13 bench repos: 446 programs found (116 of them cuda-samples directories), 117 skipped with a reason
  (exercise templates containing `FIXME`/`YOUR CODE HERE`, and programs that
  need cuDNN, NCCL, MPI, OpenGL, PyTorch, or the CUTLASS include path)

**Not done:** nothing here has been compiled with `nvcc` — the Mac has none.
The Colab harness was exercised only against a stub compiler, so the first
real run will find recipe bugs; a build failure is recorded, never fatal.

## Colab baseline

One notebook per bench repo in `oracle/colab/bench_<folder>.ipynb` (generated by
`python3 -I tools/cuda_projects.py notebook`; do not edit them by hand). Each
runs only its own repo. Runtime → GPU, Run all. It fetches the bench repos at the pinned commits, builds each
program with `nvcc -arch=native`, runs it twice, and returns
`cuda-projects-baseline-<folder>.tgz` (for example `cuda-projects-baseline-SGEMM_CUDA.tgz`). Unpack it under `RESULTS/cuda-projects/<gpu>/`.

Everything printed in a notebook, including the output of every shell command,
is also saved to `/content/logs/bench_<folder>.log`. That log is in the returned
tarball next to `out/`.

The bench cell is rerunnable and resumable. Results are saved after every
program, so running the cell again keeps everything that finished and runs only
what timed out or never ran -- a stopped cell or a dropped session continues
where it left off (`--resume`). Raise `RUN_TIMEOUT` in the cell first if a
program is merely slow. Each run that times out is also restarted once at 3x its
limit before it is recorded as a timeout. With nothing left, the cell does nothing.

Per program it records: build status and compiler output, exit code, SHA-256 of
stdout, whether the two runs agreed (`deterministic`), and PASS/FAIL markers in
the output. A hash is only a reference where `deterministic` is true.

Caveats that change how to read a result:

- `NVIDIA/cuda-samples` master targets CUDA Toolkit 13.4; Colab ships 12.x, so
  some samples will fail to configure. That is a Colab limit, not a corpus
  defect.
- Colab's free GPU is a T4 (sm_75). Programs needing sm_80+ fail there; rerun on
  an L4/A100 runtime to cover them.
- `SGEMM_CUDA`'s CMake hard-codes sm_86, so the harness compiles it directly.
- One Colab GPU is one sample of a CUDA host, the same as the RTX 5080.

## Ready, and what is left to retest

- `ready/<dir>/` + `ready.json`: the 381 programs that built and exited 0 clean on a real GPU, laid out as upstream (so
  relative `#include`s resolve) with the headers and sibling sources they need, every file hashed. `patched` entries are the
  repaired copy that passed (`upstream_sha256` is the original). Human index: `RESULTS/cuda-projects/READY.md`.
  This is the translator's input for bench repos. `python3 -I tools/cuda_projects.py ready` re-verifies the hashes.
- `retest.json` + `RESULTS/cuda-projects/RETEST.md`: the 22 real programs that have not passed, each with the GPU or host it
  needs (T4, A100/L4, 2+ GPUs, an OpenGL desktop, Jetson, CUDA 13.4) and what changed since it failed.
  `oracle/colab/bench_retest.ipynb` ran the Colab-able ones on a T4 and an A100; nothing is left for Colab (3 failed identically on both, 19 need other hosts).

## Results ledger

`RESULTS/cuda-projects/LEDGER.md` is the index of every bench result: one row
per repo per GPU, then a page per repo listing each program as `reference`,
`pass-only`, `silent`, `suspect` or `build-fail` (with the first compiler
error). Other sessions should cite it rather than re-read the raw JSON. After
unpacking a new tarball under `RESULTS/cuda-projects/<gpu>/`, run
`python3 -I tools/cuda_projects.py ledger`.
