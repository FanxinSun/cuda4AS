## Objective and prerequisites

Establish participation, visibility, ordering and progress for the finite
language slice required by reduction, tiled matmul and histogram. Require
verified address-space mapping and M3 launch/order behavior. Treat GPU execution
width, CUDA logical warp membership and barrier scope as separate concepts.

## Participation and memory semantics

Freeze block dimensions, partial tail behavior, shared allocation sizes and
what constitutes a uniform barrier. Uniform barriers are not a blanket rule
that source programs containing syntactically conditional barriers must all
fail; use the declared analysis boundary and reject cases it cannot establish
as safe. Never remove a necessary barrier simply to compile.

A Metal fence must match the actual storage backing the data. If a later shared
memory spill uses a device buffer, threadgroup-only fences are not sufficient
by assumption. The 48 KiB oracle is held for M6 unless explicitly qualified;
small on-chip shared tests do not prove a spill strategy.

For warp operations specify logical warp size, active mask, participating lanes,
shuffle source validity and partial final groups. A hardware SIMD width of 32
alone proves none of the mask/participation semantics. Unsupported masks must
diagnose rather than compute a plausible result from unrelated lanes.

Atomic contracts include operation, operand/result width, signedness, address
space, ordering and scope. Start with the operations required by the exact
histogram contract. Do not extrapolate to 64-bit atomics, floating atomics,
system scope or lock-free progress; those need separate M6 evidence.

## Test matrix

Uniform barrier producer/consumer tests verify actual data visibility.
Negative nonuniform-barrier fixtures must fail safely before unsafe dispatch.
Warp tests include partial groups, singleton/empty masks where specified,
noncontiguous masks and invalid source lanes with declared behavior.
Atomic tests include maximal contention, distributed bins, skewed input,
boundary counts, return-value semantics and repeated execution.

Reduction tests vary legal tree/size boundaries under frozen floating profiles.
Matrix tests include partial tiles in new fixtures. Histogram exact counts and
sum conservation expose lost updates. Use fixed seeds and preserve failures
instead of retrying until one success appears.

## Progress and acceptance limits

Use bounded time/resource limits for safe enrolled inputs. A timeout,
intermittent mismatch or unexplained dependence on group scheduling blocks
acceptance. Do not test global-grid synchronization by assuming all blocks
are co-resident; eligibility/progress belongs to M6's separate gate.

Return lowering/spec matrix, verifier diagnostics, fixtures, raw native results,
target/resource identity and repeated-run evidence. Accept only the finite
qualified operations; unsupported concurrency is an explicit limitation,
not permission for CPU fallback or silent serialization that changes the claim.
