# M4-2 — Pointer provenance, types and address spaces

Parent step: M4-2 in [M4](../M4.md).
State: PLANNED_NOT_AUTHORIZED; inherits M4's finite language profile.

## Objective and semantic boundary

Preserve compiler type/address-space facts and model pointer identity across
distinct buffers, offsets, aliases and device calls. An ordinary Clang pointer
may have unknown address space; a versioned entry ABI can make a bounded lowering
decision without fabricating compiler evidence. R1's vector_add-only rule is not
a universal pointer conversion policy.

Use clang_ast.py/native_aot.py semantics, the M2B module ABI and M3 allocation
registry as starting contracts. Proposed new fixtures extend
semantic.address_space_matrix and semantic.multi_buffer_pointer_aliasing without
altering the original corpus identities.

## Detailed cases

Cover device/global, threadgroup/shared, thread/local and constant/read-only
forms only where their actual CUDA and Metal meanings can be represented.
Generic pointers are an explicit design decision; do not equate generic with
device storage or reclassify constant data because the backend wants a buffer.

Exercise independent A/B/output allocations, interior offsets, legal aliases,
read-only qualifiers, alignment, struct/array indexing within the supported
slice and cross-TU argument passing. If pointer comparison/difference or
pointer-to-integer casts are outside the slice, issue stable diagnostics.
Do not infer non-aliasing from variable names or optimize overlapping operands
as independent without justified IR attributes.

Negative fixtures include explicit incompatible spaces, unsupported generic
pointers, writes through constant/read-only view, misalignment, offset overflow,
one-past dereference, stale allocation, forged ABI profile and mismatched
callee signature. Undefined source behavior should be rejected or labeled as
outside the supported contract, not assigned a fabricated CUDA result.

## Verification and artifacts

Portable verifier tests check typed memory operations, canonical types,
serialized facts/lowering provenance and exact rule version. Native tests
confirm independent resource binding and visibility with distinct recognizable
input patterns and guard regions. Use an independent CPU/specification model
for legal cases; a backend echo test is not enough.

Return conversion matrix, ABI rule specification, typed IR examples, fixture
manifest, outputs, diagnostics and target-specific result records.
A failure identifies whether it is compiler import, ABI lowering, runtime
allocation binding or backend memory semantics; do not combine them into a
generic numeric mismatch.

## Stop and acceptance

Stop for ambiguous compiler facts not covered by a declared rule, missing
runtime provenance, incompatible module ABI or a proposed new language feature
outside scope. Acceptance covers only the supported matrix. No managed memory,
arbitrary virtual addressing, sparse resources or CUDA pointer-bit-pattern
compatibility is implied by correct buffer offsets.
