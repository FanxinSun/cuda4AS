## Objective and inputs

Produce a no-argument delivery whose contents match the accepted corrected
frontend, current inventory and immutable fixture/golden inputs. The package,
runner, manifest and result analyzer must agree on schemas and member identities.

Relevant existing files are package_m2a.py, verify_m2a_package.py,
run-m2a-native.sh, run-m2a-native-aot-vector-add-all-in-one.sh,
bootstrap-m2a-native-aot-probe.sh and artifacts under tools/m2a.
Inspect and deliberately choose the delivery entrypoint; do not preserve a stale
wrapper's hard-coded package binding just because shell syntax passes.

## Package correctness

Identify compiler-semantic schema, source-location schema, facade version/hash
and ABI-lowering profile separately. Preserve expected.json and member manifest
identities. Validate reference bytes independently from generated output.

The prior M1 analyzer bug compared a packaged README against a later checkout
README. Avoid that pattern: validate against the immutable member hashes recorded
for this exact artifact, not a mutable working-tree file. Package regeneration
creates a new artifact identity; it does not retrofit an old return.

Use deterministic packaging where feasible: stable ordering, normalized metadata
and an explicit policy for timestamps. If repeat builds differ, explain which
fields differ and still bind the exact delivered artifact; do not claim byte
reproducibility without checking it.

## Portable and publication checks

Run syntax checks, verifier tests, full existing regression suite and the clean
export's no-Clang path. A portable skip must preserve exit77/NOT_RUN. Test
missing input, wrong member hash, stale package/schema, pending binding and
paths with spaces. The runner must keep prior result directories untouched.

Verify actual remote ref and tree after publication; a local commit or successful
queue does not prove delivery. Test acquisition against the established remote
and task branch, accounting for upstream mismatch and fast-forward history.
Git pull does not switch branches. Branch preparation or recovery belongs in
the tracked script where feasible; incompatible history/access is an explicit
blocker, never a download or pasted-source fallback.

The owning executor must use the installed all-in-one-probe skill and candidate
message preflight when it eventually delivers human instructions. The interface
is visible Git pull followed by one no-argument /bin/bash launch of the real
relative script. No instructions are issued by this subplan.

## Stop and closure

Stop for missing required approved inputs, secrets/private data in the payload,
unavailable remote access, incompatible user history or unverified binding.
Do not force-push, change unrelated branches or erase earlier runs.
Completion is exact published delivery plus portable validation; native truth
remains the responsibility of M2A-R2-3 and independent review in -4.
