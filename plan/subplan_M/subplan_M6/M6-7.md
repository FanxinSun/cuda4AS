## Objective and prerequisites

Qualify Celeritas 0.6.3, unmodified, as a W-SCIENCE workload on Apple GPUs,
and caloml's `Par04-bench` as the R-APP application that consumes it. The
sample was chosen on 2026-10-21 because it is a real scientific code that
reaches CUDA only through CMake and a library, and because it carries its own
oracle (unit tests with built-in expected values; caloml's RTX 5080 outputs).

Prerequisites: TK-2 accepted (S0–S3 on the M1 Pro with path accounting); for
S5 onward, the double build, which is the FP64 decision of master §3 and §8
(D1: soft64, IEEE binary64 memory format, RN-even, single-rounding `fma`).

## Rules carried over from the caloml record

- Celeritas and caloml are not edited. Configure-time options are allowed; a
  patch to a source file is not. Mac-specific decks and run scripts live in
  `samples/caloml/`.
- Every download, build and install goes into `~/system-env`, one dependency
  at a time, only when its stage needs it. Geant4 is not a Celeritas
  requirement and waits for S4.
- Compatibility first: a refused or absent construct outranks any speed
  number from the same run.

## Decisions carried over (user-accepted 2026-10-26; now master §3)

- D1 — FP64: bring-up on `-DCELERITAS_REAL_TYPE=float` first; the double
  build's `double` is IEEE soft-double (`soft64`), correctly rounded RN-even
  with a single-rounding `fma`, IEEE binary64 in memory; df64 is not the
  default and may return only as an opt-in fast mode. Open items from the
  record: the soft64 transcendental library (`sincos`, `exp`, `log`); the
  prototype in `probe/p10_fp64.swift` rounds toward zero; `atomicAdd(double*)`
  accuracy is checked against a sequential sum in arrival order and its lock
  is slow (2.6 s for 2^16 adds to one address on the M4).
- D2 — Thrust: stock CCCL pinned to 3.2.x through the compiler; `blockIdx`
  from a per-launch arrival ticket; `__threadfence()` → device-scope
  `seq_cst` fence; acquire/release → `seq_cst` (MSL 3.0–3.2 refuse them); no
  multi-pass fallback. Re-check when the SDK moves to Metal 4.
- D3 — device pointers: `MTLBuffer.gpuAddress`; every live allocation
  resident for every dispatch; `cudaMemcpy` maps an address to (buffer,
  offset).
- D4 — caloml paths: `samples/caloml/` carries rewritten copies of the decks
  and its own run scripts; caloml is not touched.

## Boundaries

No source patch to Celeritas, caloml, Geant4 or CCCL. Celeritas 0.7.0 exists
(2026-10-11); 0.6.3 stays pinned to match caloml. `size_type` is 64-bit in the
CPU builds and 32-bit on the device, so comparisons stay at the physics level.
Nothing here lifts the FP64 hold by itself: the double build is accepted only
through M6-3's FP64 edge suite and this step's RC-SCI-1 contract.
