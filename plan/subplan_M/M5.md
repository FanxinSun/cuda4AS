## Objective and entry

Make a declared R-LIB surface useful and trustworthy without counting ordinary
Metal/MPS calls as CUDA-library compatibility. Require accepted compiler,
runtime, memory, ordering and numerical contracts for the selected API.
A general library roadmap does not make every API part of the first deliverable.

Freeze a recurring-workload need before choosing the first surface. The default
candidate for review is bounded FP32 matrix multiplication, not an automatic
cuBLAS implementation decision. The exact API/header version, workload and
numerical tolerance remain explicit enrollment choices.

## Candidate surface map — not an execution order

| Surface | Potential reuse route | Required compatibility proof or hold |
|---|---|---|
| BLAS / Lt | Owned adapters to qualified Metal/MPS operations or owned kernels. | CUDA layouts/transposes/scalars/strides/stream/workspace semantics; Lt heuristics and algorithm IDs are not presumed equivalent. |
| RNG | Owned or qualified generator implementation. | Exact named algorithm/seed/subsequence/offset or a separately declared statistical R-APP route; not interchangeable random values. |
| DNN | Narrow selected operation adapters. | Layout, dilation/padding, gradients, algorithm/workspace and precision modes; no complete cuDNN claim. |
| FFT | Qualified backend or owned transforms. | Direction, scaling, strides/batches, complex layout, plan lifetime and stream semantics. |
| Sparse / solver | Workload-selected narrow operations. | Format/index base, pivoting/convergence/residuals and unsupported dtype/layout boundaries. |
| NCCL / collectives | Explicit future alternative or unsupported. | No single-device launch counts as multi-device/distributed compatibility. |
| CUB / Thrust | Compiler/template and algorithm support, not simply a binary-library shim. | Exact template instantiations, iterator/type/algorithm semantics and device-link prerequisites. |

No third-party license, download or installation is presumed approved. VF64
source/license uncertainty remains a hold, not a library dependency to import.

## API and numerical contract

Document C versus C++ linkage, ABI widths, enum values, handle/thread ownership,
host/device scalar pointer mode, row/column-major interpretation, leading
dimensions, transpose/conjugate flags, offsets, batches and aliasing.
For every unsupported parameter combination specify deterministic error behavior;
do not call a different operation and return success.

Bind numerical profile to dtype, accumulation dtype, math mode, contraction,
reduction algorithm and backend version. Strict/compatible/fast results occupy
separate rows. Library algorithm heuristics cannot change tolerance or determinism
silently. Workspace limit and allocation strategy are observable resource facts.

## Validation

Use small independently calculable cases plus meaningful larger shapes under
a fixed memory budget. Include zero/one dimensions if supported, odd dimensions,
non-contiguous leading dimensions, transposes, mixed offsets, adversarial values
and repeated handle/stream use. Separate numerical error from memory corruption.

Negative cases: invalid dimensions/strides, wrong enum, unsupported dtype/mode,
insufficient workspace, invalid handle, overlapping operands where prohibited,
wrong pointer mode, dependency/version mismatch and asynchronous failure.
Compare with CPU/specification and an independently identified NVIDIA reference
where available. Absence of a reference is recorded, not fabricated.

Benchmark only after correctness; backend time alone excludes adapter/transfer
cost and is insufficient for end-to-end value. Optional performance data feeds M7.

## Deliverables, stop and acceptance

Proposed deliverables: docs/m5 API contract, tests/m5 fixtures, versioned library
adapter code, library/schema manifest, native run evidence under RESULTS/m5 and
a per-symbol/mode support matrix. These paths are planned, not current artifacts.

Stop when the selected library requires an unqualified language feature, a new
license decision, an install or expanded resource budget. A direct MPS application
rewrite is R-APP and must not be relabeled R-LIB to close this milestone.

Acceptance requires the selected unchanged caller and contract matrix to pass,
not the entire CUDA library catalog. New APIs get new scoped child work and
re-estimation after the first surface is measured.
