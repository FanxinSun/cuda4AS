## Objective and prerequisites

Improve the measured bottlenecks of accepted-correct routes and disclose where
cuda4AS is slower or less capable. Competitor feature/spec numbers are context,
not a reason to bypass the progressive proof sequence. Earlier milestones may
collect initial diagnostic timings after correctness; M7 owns sustained tuning.

Require stable fixture/profile/target identities and successful result contracts.
Freeze the workload's practical deadline/throughput/memory requirements before
turning any performance target into a gate. Historical aspirational ratios are
not accepted requirements or measured results.

## Comparator contract

Use native Metal on the same Apple target for a platform-local reference when
available. Use the NVIDIA oracle/workload on its recorded hardware as contextual
portability/value evidence, not a like-for-like compiler speedup denominator.
R-LIB and R-APP have their own matched backend/algorithm baselines. Record missing
comparators as unavailable; do not invent measurements or buy new hardware.

Match shapes, input bytes, precision/profile, algorithm semantics, initialization,
layout, transfer boundaries and synchronization. If algorithms differ, describe
that comparison explicitly. Report hardware, OS/SDK/compiler/backend versions,
power/thermal context and competing load. No upstream marketing number is a
substitute for a reproducible measured baseline.

## Measurement and experiment detail

Measure build time separately from runtime: frontend/import, IR/link, MSL/Metal,
metallib, host/native link and package size. Runtime measurements distinguish
first pipeline use, warm dispatch, copy/transfer, synchronization and end-to-end
wall time. No runtime compilation is allowed merely to improve apparent AOT
build convenience; if pipeline creation has a cost, report it at the right point.

Use a predeclared warmup, number of samples, timing resolution, batching and
outlier policy. Retain median, spread and tail statistics alongside raw samples;
avoid only best-of timings. If the environment is noisy, report uncertainty and
defer the claim rather than deleting unfavorable runs. Separate sustained
throughput from short bursts and report thermal drift when observed.

Track peak allocations, temporary workspace, transfer bytes, residency and disk
artifacts. Unified memory does not make transfers/synchronization disappear.
Do not reinterpret per-buffer limits as total memory, or larger virtual/coded
capacity as resident GPU capacity.

## Optimization guardrails

Eligible hypotheses include eliminating redundant copies, safe buffer reuse,
kernel fusion under preserved ordering, specializing a verified ABI, reducing
frontend overhead, improved tiling and qualified library algorithm selection.
Each proposal must name the semantic assumptions it depends on and the regression
cases that could invalidate it. No automatic feature expansion accompanies tuning.

Fast-math, reassociation, contraction, reduced precision and nondeterministic
algorithms need their own declared numerical profile and pre-frozen contract.
They cannot replace strict results or silently relax science/ML acceptance.
A faster wrong answer or unsupported CPU fallback is not an optimization.

## Validation and deliverables

Proposed benchmark records under RESULTS/m7 contain fixture/source/input/golden
identities, environment, argv, raw timings, profile, correctness, memory and
comparators. Add tests for timer unit errors, missing synchronization, mismatched
workload identity, empty sample sets and contamination of first-use/warm results.

A benchmark report must show both regressions and improvements across the frozen
set. Keep broad corpus coverage separate from the subset actually benchmarked.
Do not present a single vector-add ratio as system-wide speed or as full CUDA
compatibility. Record the executor's optimization budget and stopping threshold
before work; re-estimate after baseline instead of promising universal parity.

## Acceptance and stop

Accept qualified, reproducible measurements even when they show the route is
slower. Performance acceptance is determined by the enrolled workload contract,
not a blanket must-beat-NVIDIA rule. Stop for correctness regression, excessive
variance, resource cap, undocumented backend algorithm change or exhausted
bounded budget. Follow-up tuning remains a separate scoped decision.
