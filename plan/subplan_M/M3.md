# M3 — Runtime core, memory and execution ordering

Parent step: M3 in [the master](../PLAN.md).
State: PENDING; requires its own approved execution scope.

## Objective and prerequisites

Make the minimum CUDA runtime surface dependable beyond one successful launch.
M2A/M2B's narrow host harness is evidence to preserve, not proof of general
allocation, error, stream or lifetime semantics. Require accepted core compiler,
ABI, AOT and linking evidence before expanding the runtime.

Freeze exact runtime API signatures, supported flags/default-stream mode and
error behavior. Start on the recorded M1 Pro with no CPU fallback or runtime
compilation. Alternate devices/platforms are separate target qualifications.

## Inputs and proposed deliverables

Current starting point: tools/m2a/runtime.mm and aot_manifest.py, the unchanged
vector_add oracle and the M2B linked-image contract. Proposed new runtime tests
belong in tests/m3 and result records in RESULTS/m3; paths are not assertions
that those components already exist. Carry source/manifest schema versions
through the public API, internal buffer registry and launch packet.

## Memory and pointer contract

A CUDA-like pointer must map to a specific allocation and byte offset; multiple
buffers cannot collapse into a single backing-buffer assumption. Specify
alignment, zero-size allocation, size arithmetic overflow, subranges, aliasing,
copy overlap policy, use-after-free and double-free behavior. Invalid host input
must not corrupt the registry or cause misleading GPU output.

Record individual maxBufferLength separately from recommended/available total
working-set limits. An 8 GiB individual limit is not a total GPU-memory claim.
Do not treat unified memory as unlimited, zero-cost or free of ordering.
Stress incrementally below a declared cap; no memory-pressure crash experiment
or full-machine exhaustion is implied.

## Ordering and errors

Freeze legacy versus per-thread default-stream behavior instead of mixing them.
State whether pageable/pinned host memory and async copies are included; reject
unimplemented semantics rather than silently synchronizing while claiming async.
An event records completion in its stream, and a wait creates the declared
dependency. Test two streams with observable producer/consumer data and without
accidental host synchronization that would mask a bug.

Separate launch-validation errors from command-buffer/GPU execution errors and
state when each becomes observable. Specify event/query/synchronize semantics,
device-lost handling, timeout reporting and cleanup after partial construction.
Cancellation/time limits preserve logs and do not report an unfinished dispatch
as a successful kernel. No retry on CPU is allowed.

## Validation matrix

| Area | Positive coverage | Negative and stress coverage |
|---|---|---|
| Allocation | Multiple independent buffers, offsets, aligned scalars, repeated lifecycle. | Overflow, oversize, invalid/stale pointer, double free, resource exhaustion under cap. |
| Copies | H2D/D2H and declared D2D with exact byte patterns and offsets. | Out-of-bounds, unsupported direction/flag and invalid lifetime. |
| Launch | Zero/tail-sized cases if declared, exact ABI and bounded grid dimensions. | Wrong argument count/type, absent entrypoint, unsupported grid/block size. |
| Ordering | Same-stream order, event completion and explicit cross-stream dependency. | Missing dependency, lifetime race and deferred error visibility. |
| Device | Stable supported dispatch and recorded identity. | No device, unsupported architecture/profile, malformed manifest and unsupported flags. |

Map semantic.runtime_ordering_errors and both architecture_dispatch cases to
this milestone. Broader address-space/aliasing semantics are refined in M4; M3
must already provide the buffer lifetime/offset behavior they rely on.
Use the vector_add contract as a regression, not a substitute for ordering tests.

## Artifacts, stop gates and acceptance

Return the API/error/flag matrix, target/resource identity, tests and fixture
revisions, command/dispatch traces, outputs/comparators, leak/resource accounting
and independent analysis. Portable tests validate logic; native concurrency
claims require native evidence. Timing overhead is diagnostic at this stage.

Stop for unexplained nondeterminism, missing error propagation, unsafe lifetime,
unbounded progress or changed target assumptions. A timeout is not success.
Acceptance requires the declared runtime surface and negative diagnostics to
pass; unsupported breadth stays explicit. No external-memory interop, managed
paging, multi-GPU or complete CUDA Runtime API claim follows automatically.
