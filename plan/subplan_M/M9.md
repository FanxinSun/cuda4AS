# M9 — Release readiness, compatibility claims and maintenance

Parent step: M9 in [the master](../PLAN.md).
State: PENDING; release readiness does not authorize a release, merge or tag.

## Objective and entry

Audit what can truthfully be delivered and supported from the accumulated
evidence. Require accepted results for every feature included in the proposed
release profile; unimplemented or failed surfaces stay explicit. Do not wait
for universal CUDA support before assessing a narrow honest profile, and do
not market a narrow profile as universal compatibility.

Freeze product/version scope, supported Apple/OS/SDK/Clang matrix, source/build
interface and numerical profiles. Backward compatibility includes user-visible
behavior and diagnostics, not only peak throughput or advertised feature count.

## Packaging and backwards-specification tests

Record installed file list, hashes, dependency/license manifest, supported
toolchain versions, driver flags, include/library search behavior, error codes
and runtime ABI. Test paths with spaces, relocated checkout/install, no optional
network access, missing dependency, partial install and deliberate wrong-version
inputs in a bounded disposable environment.

Define what upgrades preserve: source/API compatibility, link/module/manifest
format, cached artifact validation and numerical-profile meaning. Never accept
an old cached metallib solely because its filename matches. Schema migration
must preserve raw labels and provenance. Retain historical UNSUPPORTED and
PASS_CPU_EXPLICIT records; map to current reporting vocabulary explicitly,
without granting Native AOT GPU credit.

Negative diagnostics are part of the supported interface: wrong target, unsupported
dtype/flag, invalid source/IR/manifest, resource exhaustion and absent device
must produce honest errors, not a fake successful compilation or CPU result.

## Claims, reproducibility and security

Every public claim names case set, route, target/OS/SDK, compiler/backend version,
profile, evidence stage and limitations. Keep R-APP MPS success distinct from
cuda4AS compiler support; report adapted sources as adapted. Performance claims
link complete M7 records, not a cherry-picked run. A source audit is not execution.

Review licenses and provenance of facade headers, compiler dependencies, candidate
copies, packages, models/data and references. The unverified VF64 license remains
a hold. No history rewrite, secret remediation or redistribution campaign is
implied; discovering sensitive history requires a specific report and decision.

Validate archive paths/links/member sizes, manifest integrity, schema versions,
command argument handling and resource bounds. A checksum is integrity evidence,
not a signature or proof of safety. The receiver must not trust runner-provided
classification without validating its supporting evidence.

## Acceptance and deliverables

Deliver release-candidate manifest, compatibility/unsupported matrix, exact
install/run/remove documentation, provenance/license inventory, reproducibility
report, known limitations and maintenance/regression policy. Proposed docs/m9,
tests/m9 and RESULTS/m9 are new scoped artifacts when authorized.

Readiness can be rejected or limited to a narrower explicitly approved profile;
do not erase failed/NOT_RUN cases to manufacture completeness. Final reporting
must distinguish local changes, commits, remote publication and an actual release.
The present planning request performs none of those publication actions.
