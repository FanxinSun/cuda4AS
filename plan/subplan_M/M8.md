## Objective and prerequisite accounting

Qualify a useful recurring workload on the existing M1 Pro and distinguish the
job solved from the compatibility route used. An existing PyTorch/MPS path may
satisfy the user without cuda4AS; that is useful R-APP evidence but earns no
R-KERNEL or R-LIB credit. Conversely one CUDA kernel pass does not demonstrate
a working model, training loop or complete application.

Require the compiler/runtime/library evidence actually used by a cuda4AS route.
An alternative already-native framework route may not need those compiler
features, but starting that evaluation still needs its own authorized scope.
Dependencies/parallel possibilities refine the master; they are not a second
project order or permission to skip unfulfilled claim gates.

## Candidate boundaries

Candidate population includes customize-llm, CaloML, MuJoCo and optional PaP;
scientific/geometry applications may consume M6 results. Repository presence,
imports and static GPU keywords do not prove viable installed environments.
Freeze exact application/framework/operator/backend versions and licensing.

The previous PyTorch audit found CUDA 12.6+/torch_cuda build dependencies in its
audited surface. Do not assume a version string or successful MPS tensor operation
resolves c10_cuda, torch_cuda, CUDA extensions, generated code or custom operators.
Pin a coherent build matrix rather than mixing headers and binaries from
different releases. No whole-PyTorch CUDA compatibility claim is implied.

## Application result contracts

Inference records model/weights/tokenizer/preprocessing identity, input set,
dtype/quantization, operator backend, output metrics, deterministic/tolerance
policy, latency distribution, throughput and peak memory. A model loading is
not an inference pass. Preserve actual failure and unsupported-operation traces.

Training records loss/metric trajectories, gradients, optimizer and RNG state,
checkpoint/resume, data order and convergence envelope over a declared bounded
run. Small-step agreement does not prove full training equivalence. Scientific
or robotics workloads use their master RC-SCI/RC-ROBOT contracts; a rendered
image or simulator start is not domain validation.

If host computation is intrinsic or a framework falls back to CPU, disclose
which operations and costs. Such a mixed R-APP result cannot claim GPU-only
execution. An R-KERNEL case retains the no-silent-fallback boundary.

## Held optional residency/coded-tier integration

The original project's lmz/residency ambition is preserved, not silently removed.
It is a held decision under M8-6, outside the default critical path. Candidate
case integration.lmz_owned_host_harness remains NOT_RUN until selected.

Before any implementation, establish read-only/owned-input provenance, codec
format and license, decoder participation, object graph/reachability, pre-launch
residency and exact decoded bytes. Define eviction eligibility, dirty/writeback
semantics, stream/event dependencies, failure recovery and bounds. A compression
ratio is not an addressability or Metal-residency guarantee; vm_remap observations
and sparse-resource guesses do not prove general GPU demand paging.

Only an approved owned-host harness may explore this boundary. Do not modify a
third-party application or replace ordinary allocators invisibly. A positive
codec round-trip is WP1 evidence, not full residency success; full integration
needs launch/recovery/resource evidence and an explicit separate acceptance.

## Tests, artifacts and stopping conditions

Proposed tests/m8, docs/m8 and RESULTS/m8 contain environment manifests, operator
coverage, dispatch/fallback traces, immutable small fixtures, application metrics,
checkpoint evidence, utility record and reproducible instructions. Human-run
delivery uses the standing tracked/published script interface when authorized.

Include unsupported operator/dtype, out-of-budget data/model, corrupted checkpoint,
changed backend version, wrong numerical profile, missing custom CUDA extension
and recovery/repeated-run tests. Preserve scientific/ML validation failures.

Stop for missing resources/access, acquisition needing permission, framework
ABI mismatch, unbounded fallback, unsupported precision or invalid comparison.
Do not buy a larger Mac or lower model/data requirements to produce a pass.
Useful slower offload is acceptable only when the frozen deadline/value contract
is met. Finish with separate verdicts for technical correctness and practical use.
