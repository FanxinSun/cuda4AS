# M5-2 — First finite R-LIB implementation contract

Parent step: M5-2 in [M5](../M5.md).
State: PLANNED_NOT_AUTHORIZED. The parent M5-0 selects the operation first.

## Objective and selection boundary

Implement the first declared library surface after its workload need and
CUDA-facing API version are frozen. The concrete design below uses bounded
FP32 GEMM as the planning candidate so the work is reviewable. It does not
pre-approve cuBLAS, every GEMM variant or an API choice.

If M5-0 selects another surface, add a clearly marked replacement refinement
and retire the inapplicable GEMM-specific text without deleting it. Maintain one
active order; do not improvise a different API during implementation.

## Bounded GEMM candidate detail

Declare whether the first operation is the selected SGEMM-style single call or
another exact API. For SGEMM-like semantics, specify C = alpha*op(A)*op(B)+beta*C,
the CUDA API's column-major conventions, m/n/k, transpose combinations, lda/ldb/ldc,
scalar pointer mode, allocation offsets and alias restrictions. Device pointers
must resolve through qualified runtime allocation identity.

A row-major Metal implementation may use a proved transpose/layout mapping, but
tests must detect swapped m/n, swapped A/B, wrong leading dimension and omitted
beta*C. Padded leading dimensions, non-square/odd shapes and nontrivial alpha/beta
are mandatory; square contiguous alpha=1/beta=0 alone is insufficient.
Freeze zero-size behavior and parameter-validation order where the API requires it.

Backend fusion, reduced precision and algorithm heuristics must be explicit
numerical/profile choices. Do not automatically inherit a backend's fast mode
for strict compatibility. Workspace and temporary allocations count against the
resource envelope; hidden global synchronization invalidates an async claim.

## Validation and evidence

Use exact small representable matrices, sign/cancellation cases, seeded ordinary
matrices and declared special-value cases. Independent CPU/specification
calculations and identified NVIDIA results supply references where available.
Define absolute/relative/ULP or residual thresholds before observing candidate
output, tied to dtype, accumulation and dimension regime.

Negative tests cover invalid transpose/enum, inconsistent leading dimension,
negative/overflow dimensions, wrong scalar mode, invalid handle/stream,
out-of-range pointer, unsupported dtype/mode and insufficient workspace.
Concurrent handles/streams must not share mutable state accidentally.

Deliver header/ABI manifest, adapter mapping, operation fixture identities,
backend/compiler/runtime revisions, numerical profile, output errors and
native dispatch evidence. Host-side adapter tests are not a native library pass.

## Stop and completion

Stop for missing backend semantics, dependency/license decisions, incompatible
runtime pointer model or a need to broaden precision/API scope. A direct MPS
rewrite with changed calling code remains R-APP, not the selected R-LIB proof.
Completion covers only the explicit operation/mode matrix; adding Lt heuristics,
batched variants, DNN, RNG or other libraries requires new scoped work.
