## Objective and entry

Expand from the proven vector-add path to a small, coherent CUDA semantic
profile covering the first five unchanged oracle programs and useful WP1/WP2
extracts. Coverage means semantics and diagnostics, not the number of parsed
tokens or functions. Require accepted M2B compiler/link and M3 runtime contracts.

Freeze the Clang/facade/IR/MSL versions, exact enrolled sources, source-language
subset and target profile. The compiler owns semantics; source spelling or a
hard-coded expected expression may not replace the AST/IR.

## Inputs and ownership

Start with tools/m2a/clang_ast.py and native_aot.py, existing facade/manifest
and oracle/src. Proposed tests/m4 contains newly enrolled positive/negative
fixtures; docs and RESULTS records must name their exact versions. Reuse the
M0 corpus IDs and keep independent case classifications.

## Language contract

Preserve integer width/signedness, promotions, casts, comparison predicates,
short-circuit behavior, loop control, indexing, function signatures and memory
effects. Define treatment of CUDA undefined/unspecified behavior rather than
testing undefined source as a required deterministic output. Reject unsupported
constructs with source location and a stable diagnostic category.

Floating-point operations carry profile-specific contraction, reassociation,
denormal and special-value rules. Do not fold strict expressions using fast-math
assumptions. Double declarations are not made FP32 merely because the first
profile is FP32/int32; unsupported FP64 is diagnosed and held for M6 decisions.

## Oracle and semantic acceptance

| Corpus family | Required contract | Important boundary |
|---|---|---|
| oracle.vector_add | Regression of accepted immutable output. | Same fixture/input/hash; do not recalculate golden bytes from the new backend. |
| oracle.saxpy | FP profile plus bounds/tail correctness. | Contraction and tolerance chosen before seeing output. |
| oracle.reduce_sum | Declared reduction tree/order and floating error contract. | Bitwise equality only where the contract truly requires it; no post-hoc tolerance relaxation. |
| oracle.matmul_tiled | Indexing, tiling and shared-memory synchronization. | Partial tiles/tails get new frozen cases; padding must not hide out-of-bounds access. |
| oracle.histogram_atomics | Exact counts and conservation. | Collisions, skew and zero/edge inputs expose atomic races. |
| semantic.address_space_matrix; semantic.multi_buffer_pointer_aliasing | Explicit legal/rejected conversions and allocation identity. | No forced global/device mapping of unknown compiler facts. |
| semantic.warp_masks_partial_shuffle; semantic.uniform_barrier | Lane participation, masks and visibility. | Metal SIMD width matching CUDA warp width alone is not semantic proof. |
| diagnostic.divergent_barrier | Predeclared rejection of unsupported/unsafe participation. | Never execute a known hanging input to see whether it eventually completes. |

shared_48kb, grid_sync, atomic64, FP64 and PTX matrix instructions remain explicit
M6 frontier decisions unless a separately authorized M4 slice truly qualifies
one. Passing a small histogram does not claim every atomic type/scope.

## Tests, resources and stop conditions

Use property/metamorphic tests alongside fixed goldens: index bounds, permutation
where legal, histogram conservation and independent small CPU/spec calculations.
Freeze randomized seeds and retain counterexamples. Exercise boundary sizes and
partial groups without mutating existing immutable oracle enrollment.

Require negative fixtures for malformed compiler IR, illegal casts, alias-range
violation, unsupported intrinsic/precision, nonuniform barrier and unsupported
warp mask. Portable verification never substitutes for native visibility tests.

Keep tests bounded and instrument timeouts; do not use scheduler luck as a
forward-progress argument. A semantic mismatch blocks performance tuning.
If a required operation needs a different ABI or runtime guarantee, return the
specific dependency and decide a bounded correction; do not bypass checks.

## Deliverables and claim limit

Return coverage/spec table, compiler and runtime changes within the future
scope, fixture manifests, positive/negative results, independent comparisons
and source-level diagnostics. The milestone proves its enrolled language slice,
not CUDA C++ completeness, all CUB/Thrust templates or entire surveyed projects.
