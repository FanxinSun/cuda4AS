## What it is, and why it is in this drop

This is lmz's rANS decoder ported to Metal — written on a Linux box with no
Apple GPU and, as its own README says, **never run on any Apple GPU**. It is
gate **G-C6** in `docs/cuda-on-apple-silicon.md`: the coded tier of §2.7 is
`vram/`'s V-coded weights decoded on the way into the matrix unit, and that
whole line of the design is unproven on Apple silicon until this harness
prints `byte-identical`.

Its three kernels also happen to be the best available test of the
`simdgroup_barrier`-under-divergence question that `p3_lockstep` asks
directly: `lmz_decode_plane_direct` has no divergent barrier and is correct by
construction, while `lmz_decode_plane_prefetch` relies on the barrier being a
memory fence over a SIMD-group that runs in lockstep. If the direct kernel
verifies and the prefetch kernel does not, that is the answer, and p3's A1 and
A2 cases should say the same thing independently.

## The data in `../data/`

Not lmz's. It was generated by `cuda4AS/tools/prep_synth_shared.py` — our
file — which calls lmz's own encoder through lmz's Python API and verifies
every stream through lmz's own decoder before writing it. See that script's
docstring for why neither of lmz's two existing preparation scripts could be
used directly: `bench.swift` reads only the **shared-table** container shape,
`prep_shared.py` writes that shape but needs a 3 GB safetensors checkpoint,
and `prep_synth.py` needs no checkpoint but writes the **per-chunk** shape,
which `bench.swift` would misparse.
